## 1. 시장·환경 검토

- RealWorld 프로젝트는 150개 이상의 구현체가 존재하는 성숙 생태계
- 공식 API 스펙과 Postman 테스트 suite가 제공되어 **구현 검증이 자동화** 가능
- Bootstrap 4 기반 공식 테마가 제공되어 프론트엔드 디자인 부담 최소
- Medium.com 클론이라는 명확한 도메인 — 복잡도가 적절히 통제됨

## 2. 기술 타당성

**아키텍처**: 프론트엔드(SPA) + 백엔드(REST API) + DB 3-tier 구조

- **API 스펙 확정**: 모든 엔드포인트·요청/응답 형식이 문서화됨 (18개 엔드포인트)
- **인증**: JWT 기반 — 표준 라이브러리로 구현 용이
- **데이터 모델**: User, Article, Comment, Tag, Follow, Favorite — 6개 엔티티로 관계가 명확
- **프론트엔드**: 9개 라우트, Bootstrap 4 테마 — 추가 디자인 불필요
- **CORS**: 공식 스펙에 명시 — 로컬에서도 FE/BE 포트 분리 시 필요, 추후 분리 배포에도 대응

**기술적 난이도**: 중하 — 도메인이 단순하고 스펙이 명확하여 설계→구현 직선 경로

## 3. 비용·리소스 추정

| 항목 | 추정 | 비고 |
|---|---|---|
| 개발 인력 | 1인 (에이전트 지원) | 풀스택 |
| 기간 | 약 1~2주 | 기획~로컬 완성 전체 |
| 인프라 비용 | $0 | 로컬 전용 — 추후 클라우드 배포 시 무료 tier 활용 가능 |
| 외부 의존 | 없음 | 자체 인증, 자체 DB |
| 라이선스 | MIT | RealWorld 프로젝트 라이선스 |

## 4. 기대 효과

- RealWorld 스펙 100% 준수 구현체 확보
- 풀스택 개발 역량 실증 및 포트폴리오
- 에이전트 기반 개발 프로세스(DevToolKit) 검증
- 다양한 기술 스택 조합 실험 가능 (프론트·백엔드 교체 가능)

## 5. 검토된 대안

| 대안 | 장점 | 단점 | 결론 |
|---|---|---|---|
| 기존 RealWorld 구현체 fork | 즉시 시작 | 학습 효과 없음, 툴킷 검증 불가 | 기각 |
| 공식 API만 사용 (BE 없이 FE만) | 빠른 구현 | 백엔드 학습 누락, 의존성 | 기각 |
| 독자 블로그 서비스 설계 | 자유도 높음 | 스펙 불확정, 검증 기준 없음 | 기각 |
| **RealWorld 스펙 기반 풀스택 자체 구현** | 명확한 스펙, 자동 검증, 학습 극대화 | 구현 공수 | **채택** |

## 6. 추천

RealWorld 스펙 기반 풀스택 자체 구현을 추천한다.

- 스펙이 완전히 문서화되어 있어 설계 리스크 최소
- 공식 Postman 테스트 suite로 구현 검증 자동화 가능
- 프론트·백엔드 기술 스택 선택의 자유도 확보
- DevToolKit 프로세스 검증에 적합한 복잡도 (너무 단순하지도, 과하지도 않음)
- 기간·비용 대비 효과가 가장 우수

**진행 추천**: Gate A 통과 → Gate B (SRS/PRD) → Gate C (설계)로 진행
